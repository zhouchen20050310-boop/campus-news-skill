# 人、Agent、脚本与外部工具

## 分工

| 角色 | 责任 |
| --- | --- |
| 编辑 | 指定公众号与两组日期、制定价值和风格标准、最终选题、复核和发布 |
| Agent | 实际阅读原文，判断对学生的价值与时效，拆分合并事项，撰写标题、概要和正文 |
| Python脚本 | 解析TXT、核对收藏、调用API、分页与归档、验证数据对应、生成HTML及交接文件 |
| WeChat MP Tools | 维护用户登录和收藏，提供文章列表并生成原文资料 |
| all-to-xiumi | 为独立秀米编辑会话提供转换及浏览器操作实现 |

Skill 是这几部分的工作约定与可复用实现。它不内置桌面工具或模型，也不因为包含几段提示词就拥有登录权限或定时运行能力。

## 数据流

1. prepare_run.py 读取用户TXT与日期，实时检查收藏，生成 plan.json。
2. collect_articles.py 分页、下载、归档，生成阅读索引与覆盖清单。成功、失败、未知日期、越界等分别保留。
3. Agent 按阅读索引实际读 MD，需要时补读图片/PDF，生成筛选数据。不能直接复制某一期写死的推荐结果。
4. build_news.py 验证数据、原文编号和MD摘录，导出筛选记录、文案及两版HTML。它本身不调用模型或完成语义判断。
5. xiumi_adapter.py 使用外部项目进行转换与分步操作。本地转换通过、正文导入、保存、重开验收是不同状态。

当用户选有效日期不限时，plan记录 validity_mode=unrestricted、valid_start/valid_end为null；不是把日期换成一个很宽的虚构区间。

## 验证证据与限制

目前9项离线测试覆盖范围开关、缺失/重名收藏、两组日期与不限模式、范围变化、API业务错误、分页和跨账号同链接去重、TXT省略、任务续查与提交不明时不重复提交，以及筛选至排版的数据交接。

真实 Windows 本机测试使用用户指定的2个公众号，下载7篇，全部读MD，从5篇整理出10条新闻；没有补读PDF，因为MD足够。输出了两版HTML，检查桌面与390像素预览，完成17块秀米本地转换。

另有旧一期52篇记录、18项既有资讯的技术回归，只证明已有数据能通过新代码，不代表重新在线采集或重新完成语义审稿。

仍待验证：不同软件版本、不同Agent宿主、长期授权和无人值守运行，以及新版秀米在线保存重开。接口返回不证明渠道完整，工具的日期证据不等于已独立核对远端原文。

## 为什么还保留人工节点

资讯价值、校园受众和文案语气属于编辑判断；报名期限与活动日期也可能不同。保留每篇理由、证据和【待确认】，让编辑能修改选择，避免流程跑通但稿件不可用。

登录失效由本人扫码。容量不足、旧稿恢复或人工已改正文时保留编辑页；不通过删稿、反复重导来“完成”测试。

## 后续方向

- 在目标宿主开展更完整的工具接入和编辑试用。
- 验证秀米保存重开、授权失效及容量不足等交互。
- 记录采集遗漏、人工修改量与不同稿件长度的可读性。
- 进一步支持不同校园栏目和可配置排版。

这些方向尚未全部实现，不作为当前功能承诺。
